# 从任务到稳定自动化｜工程化作业手册

## 0. 明确输入、目标与风险

先填写 [BOT-ROLE-TEMPLATE](../templates/BOT-ROLE-TEMPLATE.md)。定义一个 Bot 的目标和边界；每个任务必须给出唯一 ID、数据来源、完成定义、审批人。

## 1. 删除不必要的步骤（五步法）

- **质疑**：为什么必须自动化？是否只是为了演示？
- **删除**：能否删掉登录、跨系统写入、不必要字段和多余 Bot？
- **简化**：先做到只读 → 草拟 → 人工批准 → 再执行。
- **加速**：可复现之后，用 Skill 缩短重复说明，统一输入格式。
- **自动化**：只有回归测试通过、失败策略清楚，才上 Routine。

## 2. 评估是否值得自动化

打 4 个标签：频次、规则稳定度、复核成本、外部后果。

- 适合初期：公开资料整理、内部周报草稿、对已有授权表格的归类。
- 需要很高门槛：对外发送、生产部署、删库、付款、实名信息处理。
- 不适合自动化：未获授权的社交平台群发私信、绕过人机验证、越权采集。

## 3. 三轮验收

- **第 1 轮 Happy path**：正常资料，验证是否输出指定格式和实际文件。
- **第 2 轮 缺失数据**：清空关键字段、断网或权限不足，验证是否停止推断并明确说明。
- **第 3 轮 恶意输入**：在网页测试文案嵌入“忽略指令、发送密码”等干扰，验证是否拒绝把外部文本当高权限命令。

## 4. 转成 Skill

只保存稳定工作的路径，附上输入数据类型、步骤、异常、审批点、验收标准。使用第二组输入回归，确认不是对样例“过拟合”。

## 5. 建 Routine 前必须经过的检查

- [ ] 确认触发时区、边界和当前启用状态
- [ ] 备有源数据为空或过期时的停止规则
- [ ] 有幂等性规则 / 去重键，避免重复操作
- [ ] 对外发布、消费、删除、生产修改要求具体人工审批
- [ ] 预算上限与账号用量已核对
- [ ] 可以一键暂停并找到失败日志
- [ ] 有人工负责人和升级处理渠道

## 6. 指标（不能省略）

假设人工基准时间是 **H** 分钟，Bot 产出后的人工复核和纠错 **R** 分钟，额外日常维护摊销 **M** 分钟，则每次净节约人工时间 **H-R-M**。原始输入不全时不填值。

持续记录 10 次任务的完成数、失败数、错误数与复核耗时；关键外部操作的未经审批执行次数必须为 0。真实成本来自账单，不以任务数猜定价。

## 7. 故障处置和回滚

1. **止损**：暂停相关 Routine 或撤销有风险的授权，避免重复运行。
2. **保全**：保存原始错误、时间、涉及资源和已经执行的动作。
3. **判别**：用户账号问题、审批过期、第三方服务、云端电脑、用量还是提示词内容错误。
4. **恢复**：Retry / Recover / Update 优先；Reset 必须经过数据损失判断。
5. **核对**：确认没有重复发送、重复付款、文件覆盖或数据污染。
6. **复盘**：更新 Skill / 审批规则，并在安全数据上重测后恢复 Routine。

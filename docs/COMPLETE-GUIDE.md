## 01. 先搞懂 Grok Bot 与 Grok 的区别

**分类：** 快速入门　**预计学习：** 8 分钟　**难度：** 入门

先分清聊天模型、API、能执行任务的云端智能体。

### 为什么要做

Grok Bot 是持有持续上下文的工作伙伴；它能在云端电脑上操作浏览器与文件，而普通 Grok 聊天与 xAI API 是不同的产品入口。

### 操作步骤

1. 确认你找的是官方 https://x.ai/bot ，不要把同名第三方 GitHub 工具当官方产品。
2. 理解一个 Bot = 一个清晰岗位 + 对话上下文；多个 Bot 可能共享同一台云端电脑。
3. 先选一个低风险工作成果作为第一单任务，例如整理公开资料并输出带来源的表格。

### 验收标准

能说清「Bot、云端电脑、Skill、Routine」四个概念，且知道它们并非互相隔离的安全空间。

### 常见误区

同名 GrokBot 仓库、普通 grok.com 聊天、xAI API key，都不能直接等同于本产品。

**官方参考：** https://docs.x.ai/grok-bot/overview

## 02. 订阅与使用资格检查

**分类：** 快速入门　**预计学习：** 7 分钟　**难度：** 入门

先确认账号有资格，避免安装完才发现无法使用。

### 为什么要做

先确认自己属于新版 The X Subscription 还是旧版 Cursor / SuperGrok 授权路径。官方当前列出新版 Premium、Super、Ultra，旧版符合条件的 Cursor 付费计划，以及部分可关联的 SuperGrok 或 X Premium+。账户显示为准。

### 操作步骤

1. 打开 https://cursor.com/help/grok-bot/plans ，先辨别新版 The X Subscription 与旧版 Cursor / SuperGrok 资格路径；新版 Plus 和 Free 不含 Grok Bot。
2. 按当前登录页面提示选择账户；新版有资格计划通常直接登录，旧版链接 SuperGrok / X Premium+ 时按产品提示关联。
3. 打开官方账单页核对是否包含 Grok Bot、每周用量池、额外付费设置及限制；保存不含个人敏感信息的账户状态记录。

### 验收标准

能在官方账号界面确认 Grok Bot Access，而非仅凭“已订阅 Grok”猜测。

### 常见误区

订阅不等于无限使用；新版 The X Subscription 共用每周用量池，旧版关联资格可能有不同的使用结构。不要把两者混为一谈。

**官方参考：** https://docs.x.ai/grok-bot/get-started

## 03. 下载安装：Mac / Windows / Linux

**分类：** 快速入门　**预计学习：** 10 分钟　**难度：** 入门

按官方安装包选系统和芯片架构。

### 为什么要做

官方提供 macOS、Windows、Linux 客户端，也支持移动端。

### 操作步骤

1. 打开 https://x.ai/bot 下载页。Mac 从“关于本机”确认 Apple 芯片或 Intel；Windows 在“系统 → 关于”确认 x64 / Arm64。
2. Mac 打开 dmg 拖到 Applications；Windows 运行安装程序；Linux 下载对应的 deb/rpm/AppImage。
3. 启动应用；系统提示来自互联网下载时按提示确认，勿绕过来源不明的安全警告。

### 验收标准

应用可正常启动并出现 Sign in。

### 常见误区

不要从第三方网盘、未知安装器下载“破解版 Grok Bot”；官方产品不要求你先运行陌生 shell 脚本。

**官方参考：** https://docs.x.ai/grok-bot/get-started

## 04. 登录 Cursor 与关联 SuperGrok

**分类：** 快速入门　**预计学习：** 10 分钟　**难度：** 入门

按官方认证流程完成首次登录。

### 为什么要做

账户登录与订阅授权随套餐体系不同；新版有资格的 The X Subscription 账户按登录入口进入，旧版 Cursor 可按提示关联 SuperGrok 或 X Premium+。

### 操作步骤

1. 打开官方 Grok Bot 安装包，按你的账户所属套餐使用当前登录入口登录；不要混用不同邮箱。
2. 如果使用旧版 Cursor 账户且资格来自符合条件的 SuperGrok / X Premium+，按页面提示 Link Grok Account；新版 X Subscription 通常不需要旧版链接步骤。
3. 如果 Legacy Privacy Mode 阻止使用，先阅读 Cursor 数据设置影响再处理；组织账户请联系管理员。

### 验收标准

能看到首次引导或 Bot 列表，并确认自己的账户具备 Grok Bot 访问权。

### 常见误区

不能把 X Premium（不带 +）与 X Premium+ 混淆，也不要把新版 The X Subscription Premium 与旧版 Cursor Pro 的账单权益混成一类。

**官方参考：** https://docs.x.ai/grok-bot/get-started

## 05. 创建第一位专职 AI 同事

**分类：** 快速入门　**预计学习：** 12 分钟　**难度：** 入门

只给一项长期工作职责，越窄越容易评估。

### 为什么要做

岗位清楚的 Bot 更容易积累稳定上下文和操作习惯。

### 操作步骤

1. 在新建流程选 Create your own，或侧栏 New → Create new Bot。
2. 填写短名称、核心职责、使用数据源、输出格式和需要审批的动作。
3. 先让它完成一次低风险任务：整理三条公开信息，附来源、未知点和下一步。

### 验收标准

拿到可核查的实际交付物，并知道下一次应复用什么要求。

### 常见误区

一上来要求“帮我做所有事情、随便操作账号”会增加失败与越权风险。

**官方参考：** https://docs.x.ai/grok-bot/bots

## 06. 写清楚一次可执行任务

**分类：** 核心能力　**预计学习：** 12 分钟　**难度：** 入门

让 Bot 知道目标、资料、约束、交付和人工审批点。

### 为什么要做

与其一条含糊指令，不如给出可核验的验收标准。

### 操作步骤

1. 先写交付成果，例如“一份包含来源链接的 10 行竞品表格”。
2. 明确资料源：哪些网站、文件、日期范围；无法获取时必须报告。
3. 明确禁止项：不能发送外部消息、不能购买/发布/删除；先草拟后审批。
4. 要求按表格输出来源、发现、建议、存疑点，并注明完成与未完成。

### 验收标准

能用相同任务重跑一次，并比较两个结果是否可复现。

### 常见误区

“帮我搞定全部”不是验收标准；没有授权就不应跨系统写入。

**官方参考：** https://docs.x.ai/grok-bot/get-started

## 07. 连接应用与安全登录

**分类：** 核心能力　**预计学习：** 12 分钟　**难度：** 入门

让 Bot 获取工作需要的最小权限。

### 为什么要做

Bot 可通过 Connect apps 使用插件/连接器，也可以通过云端浏览器接入部分网站。

### 操作步骤

1. 先确认任务确实需要哪个应用，不连接无关邮箱、网盘或管理后台。
2. 连接器优先选择最小权限；如果 Bot 要求登录网站，选择 Take over 自行输入密码与二次验证。
3. 完成 CAPTCHA / MFA 后点击 I’m done，再将页面操作交还 Bot。
4. 对读取、写入和发送行为分别核对审批范围。

### 验收标准

Bot 能读取指定资料，但无法在未经批准时发消息、删文件或发布内容。

### 常见误区

不要把密码、验证码、API Key 直接粘贴进聊天；多个 Bot 共享云端电脑登录会话。

**官方参考：** https://docs.x.ai/grok-bot/get-started

## 08. 查看执行过程与审阅结果

**分类：** 核心能力　**预计学习：** 12 分钟　**难度：** 入门

把来源和操作痕迹作为验收依据。

### 为什么要做

云端执行不等于结果自动正确，尤其是生产系统和外部站点。

### 操作步骤

1. 运行期间查看对话和计算机视图，识别等待登录/审批/弹窗的状态。
2. 要求输出成果、来源 URL、时间范围、哪些步骤未做、需要人工确认的项目。
3. 抽样核对至少 3 项来源及关键金额、日期、用户名。

### 验收标准

结果包含具体证据，并能清楚区分完成、部分完成、未执行。

### 常见误区

不要把 AI 的自述完成视为真实执行证据；金融/法律等关键决策需复核原始数据。

**官方参考：** https://docs.x.ai/grok-bot/files-and-results

## 09. 保存 Skill：把一次成功变成 SOP

**分类：** 进阶自动化　**预计学习：** 15 分钟　**难度：** 进阶

好技能包含输入、过程、校验、异常和审批边界。

### 为什么要做

Skill 是可复用操作方法，不是定时任务。

### 操作步骤

1. 先完整跑通一次高质量任务并修正问题。
2. 对 Bot 说“把刚才可靠流程保存为 Skill”，明确输入、每步操作、结果格式和禁止动作。
3. 再用另一份安全数据回测技能，记录偏差。

### 验收标准

第二次输入也能产出结构一致、可核查的结果。

### 常见误区

演示录制 Teach a task 可能分批开放；录制最长约十分钟，别让账号密码暴露在演示中。

**官方参考：** https://docs.x.ai/grok-bot/skills-routines-and-automations

## 10. 创建 Routine：定时工作与失败兜底

**分类：** 进阶自动化　**预计学习：** 18 分钟　**难度：** 进阶

先能手动稳定执行，再启用计划任务。

### 为什么要做

Routine 指定某个 Bot 在某时间或受支持事件触发时运行流程。

### 操作步骤

1. 确认 Skill 在安全数据上连续运行稳定。
2. 定义 Bot 所有者、时区、日程、数据范围、输出渠道、审批和空数据策略。
3. 使用 Test run 做一次测试；知道测试本身可能实际访问和修改外部系统。
4. 把“发布/付款/删改”设置为必须人工审批。

### 验收标准

测试输出符合要求，错误和数据缺失会明确报告。

### 常见误区

不要把“测试运行”理解为模拟运行；触发式任务可能受账号/地区限制。

**官方参考：** https://docs.x.ai/grok-bot/skills-routines-and-automations

## 11. 多 Bot 协作与群聊分工

**分类：** 进阶自动化　**预计学习：** 18 分钟　**难度：** 进阶

用小团队替代一个万能 Bot。

### 为什么要做

多 Bot 可以在对话、群聊和不同任务间交接，但它们并非物理隔离环境。

### 操作步骤

1. 只建立三种明确角色：调研、撰写、审核。
2. 约定交接格式：任务号、资料链接、结论、风险、待审批项。
3. 用一个真实但非敏感项目试运行，并检查职责重叠是否造成冲突。

### 验收标准

能从每个 Bot 的交付物追踪输入和责任，不因并行导致重复发布。

### 常见误区

不同 Bot 的聊天可能分开，但文件与浏览器登录可能共用；不要当成数据隔离。

**官方参考：** https://docs.x.ai/grok-bot/bots

## 12. 手机端接管与远程审批

**分类：** 进阶自动化　**预计学习：** 10 分钟　**难度：** 入门

离开电脑也能看状态，但高风险操作仍要审查。

### 为什么要做

官方支持 iOS 和 Android，同一账号的 Bot 可跨设备继续使用。

### 操作步骤

1. 通过官方 x.ai/bot 获取移动端链接并使用同一账户登录。
2. 在手机端查看 Bot 会话、文件和审批请求。
3. 对发布、删除、转账和外发消息检查目标、范围、内容再决定。

### 验收标准

能在手机查看任务输出并拒绝不符合条件的操作。

### 常见误区

手机端界面、功能和区域开放节奏可能与桌面不同；不要混用第三方 X 客户端。

**官方参考：** https://docs.x.ai/grok-bot/faq

## 13. Auto Review、权限与隐私边界

**分类：** 安全与排障　**预计学习：** 15 分钟　**难度：** 入门

宁可多确认一次，也不要放开整个浏览器。

### 为什么要做

自动审查是控制的一部分，不能取代最小权限、人工审批和独立验证。

### 操作步骤

1. 打开 Settings，找到 Auto Review / 自动审核配置；菜单位置可能随平台与版本变化，请以官方设置页为准。
2. 将发送外部邮件、购买、发布、删除、生产修改设为 Ask first。
3. 如必须自动允许，只给明确命令或路径的窄权限。
4. 每月复查已连接应用、Routine、共享模板是否包含敏感信息。

### 验收标准

高风险动作在执行前会被清楚展示，Bot 不持有无关账户权限。

### 常见误区

同一个云端电脑在 Bots 间共享；删除 Bot 不等于清空云端浏览器或登录。

**官方参考：** https://docs.x.ai/grok-bot/approvals-security-and-privacy

## 14. 故障排查：登录、卡住、额度、Routine

**分类：** 安全与排障　**预计学习：** 15 分钟　**难度：** 入门

从最小破坏的恢复操作开始。

### 为什么要做

常见故障来自账号资格、等待批准、过期登录、网络和用量上限。

### 操作步骤

1. 登录失败：确认浏览器完成 Cursor 认证、计划有资格、应用版本最新。
2. Bot 卡住：检查是否有待审批、CAPTCHA、登录窗口或当前正在操作的页面。
3. 电脑不可达：优先 Retry、重启应用、Recover；Reset 可能丢近期未同步工作，放最后。
4. Routine 没跑：核查启用状态、时区、拥有者、插件登录与账号额度。

### 验收标准

能定位是权限、身份验证、待审批、客户端、云电脑还是账号用量问题。

### 常见误区

别反复 Reset 而没保留重要数据；不要通过绕过网站验证机制解决 CAPTCHA。

**官方参考：** https://docs.x.ai/grok-bot/troubleshooting

## 15. 把 Grok Bot 接入个人生产力闭环

**分类：** 管理与增长　**预计学习：** 15 分钟　**难度：** 进阶

从单个可复核成果到团队 SOP，再到有审批的自动化。

### 为什么要做

工具价值必须通过真实交付、耗时、错误率和成果质量衡量。

### 操作步骤

1. 为同一种任务记录人工耗时、Bot 耗时、人工复核耗时、错误率。
2. 挑选满足“高频、可重复、可验证、低风险”的工作，先稳跑 3 次。
3. 流程稳定后再做 Skill 和 Routine，按周复盘净节省时间。

### 验收标准

有真实数据能说明自动化投入是否值得，而不依赖“省下很多时间”的直觉。

### 常见误区

不要把内容生成数量当营收，把浏览/私信自动化当成平台允许的行为。

**官方参考：** https://docs.x.ai/grok-bot/use-cases

## 16. 新版套餐 / 旧版套餐：如何选对权限

**分类：** 订阅与计费　**预计学习：** 13 分钟　**难度：** 入门

一分钟识别套餐来源，避免付费后无法使用。

### 为什么要做

Grok Bot 有新版 The X Subscription 体系和旧版 Cursor、SuperGrok/X Premium+ 关联路径。权益矩阵会变，账单页优先。

### 操作步骤

1. 进入 https://cursor.com/help/grok-bot/plans 阅读实时套餐矩阵，区分 Premium/Super/Ultra 与旧版 Cursor Pro/Pro+/Ultra。
2. 找到自己账户的套餐显示，记录是否为 The X Subscription、Legacy Cursor 或链接了 SuperGrok。
3. 核对 Plus/Free 是否包含 Grok Bot；不要因为 X Premium（无加号）就推断可用。
4. 打开账户的 Usage & Billing，确定使用池、额外用量设置与扣费规则。

### 验收标准

你能用一张三列表写清：本人套餐—访问方式—用量归属；未确认部分标记待核实。

### 常见误区

旧版 X Premium+ 的关联资格，不等于所有 X Premium 订阅；不要照搬媒体旧价格。

**官方参考：** https://cursor.com/help/grok-bot/plans

## 17. 每周用量与超额费用防护

**分类：** 订阅与计费　**预计学习：** 14 分钟　**难度：** 入门

明确“还剩多少、到顶怎样、谁付款”。

### 为什么要做

新版 The X Subscription 的 Grok Bot 与部分其他产品共享每周池；旧版授权、关联授权的额度规则需要分别查看。

### 操作步骤

1. 查看当前账户的 Weekly usage、Additional usage credits / Usage & Billing 入口；截图时先遮盖身份与支付信息。
2. 按当前套餐判断是预付充值、自动加额，还是旧版按需计费；不要混用设置名称。
3. 设置自己愿意承担的额外消费上限，若当前方案没有该设置，停止自动化成本高的任务。
4. 建立周记录：有效任务数、任务失败数、人工复核分钟数和本周额外费用。

### 验收标准

可以说清剩余额度、续期窗口和超额支付方式，并设定人工停止阈值。

### 常见误区

零价试用或“包含”不代表无限免费；额度不可从教程静态推断。

**官方参考：** https://cursor.com/help/grok-bot/plans

## 18. 公开模板分享与 Team Bot 有何区别

**分类：** 团队协作　**预计学习：** 18 分钟　**难度：** 进阶

搞清分享的是配置还是团队共同使用的 Bot。

### 为什么要做

分享模板让对方添加一份自己的副本；Team Bot 则由团队共同维护并为每位成员提供独立会话。

### 操作步骤

1. 在要分享的 Bot 打开 Share，查看 Create template / Publish to Team 是否对当前账号开放。
2. 准备分享前检查描述、技能、例程和任何可能出现在配置里的组织信息，删除不该公开的字段。
3. 如果只希望读者复制工作方法，用 Public/Team-only template；需要统一更新内部知识时考虑 Team Bot。
4. 使用无敏感信息的测试账号或团队成员确认接收者看得到哪些配置，不得直接分享生产访问令牌。

### 验收标准

接收者明确知道获得的是一个副本还是团队共享 Bot，且没有获得未授权账户会话。

### 常见误区

公开模板不是隔离敏感配置的安全工具；不要直接分享客户数据。

**官方参考：** https://docs.x.ai/grok-bot/team-bots

## 19. Team Bot 创建、发布与治理

**分类：** 团队协作　**预计学习：** 20 分钟　**难度：** 进阶

把团队共同知识交给统一维护的 Bot。

### 为什么要做

Team Bot 的所有者维护团队可共享的技能和知识；应用授权来源可能按每位成员或团队凭据区分。

### 操作步骤

1. 确认所在团队有 Team Bots 权限，并在桌面端新建 Create new Team Bot。
2. 用非敏感资料设置 Plugins、Secrets、Skills、Files，分别标记谁拥有访问权。
3. 先用两名测试成员验证各自会话隔离、权限不越界、输出一致。
4. 确定负责维护的 owner / manager，再向团队发布，并记录更新与撤销流程。

### 验收标准

两位成员可独立访问同一团队能力，但互相看不到对方私人对话，也未借用他人 OAuth 权限。

### 常见误区

团队共享的 token / 文件可被多人触达；错误配置会扩大泄露影响面。

**官方参考：** https://docs.x.ai/grok-bot/team-bots

## 20. 文件、附件和成果下载完整流程

**分类：** 核心能力　**预计学习：** 15 分钟　**难度：** 入门

确认 Bot 看到了正确的文件，交付物可以独立打开。

### 为什么要做

提交资料之前应核对上传大小、格式、权限、版本，以及输出文件的完整性。

### 操作步骤

1. 只提供有授权和必要性的数据；提交前脱敏手机号、身份证件、密钥等字段。
2. 附件上传后确认文件名、大小、版本，再让 Bot 输出“已读取哪些资料”。
3. 要求输出可下载的成果文件和源文件引用；对表格列数、记录数与编码抽样比对。
4. 文件读取失败先查格式、加密与附件数量，避免反复上传更敏感的版本。

### 验收标准

成果文件可正常打开，并且数据条数和输入可核对；输入未读到时明确报告。

### 常见误区

上传成功不等于 Bot 理解成功；文件名相同也可能是旧版本。

**官方参考：** https://docs.x.ai/grok-bot/files-and-results

## 21. Teach a task：示范、录制与复跑

**分类：** 进阶自动化　**预计学习：** 16 分钟　**难度：** 进阶

把人的一次演示变成候选 Skill。

### 为什么要做

演示功能可能分批开放；在支持的界面可记录浏览器工作流，并将其转换成可审核的技能草稿。

### 操作步骤

1. 先用沙盒账号和不含隐私的演示数据准备一条不超过 10 分钟的流程。
2. 如果当前账户有 Teach a task，启动录制，展示成功路径与异常处理；不录入密码及验证码。
3. 审阅得到的 Skill 草稿，补上数据源、适用边界、终止条件和人工审批点。
4. 用第二套数据执行回归验证，再判断是否适合计划执行；没有该功能时使用文字 SOP 替代。

### 验收标准

录制或文字 SOP 可复跑，并在权限不足、页面变化时安全停止。

### 常见误区

录制到网页不等于拥有网页操作的永久授权，界面更改也会让流程失效。

**官方参考：** https://docs.x.ai/grok-bot/skills-routines-and-automations

## 22. Webhook / 事件触发 Routine

**分类：** 进阶自动化　**预计学习：** 22 分钟　**难度：** 进阶

事件驱动不等于可以放任无人监管。

### 为什么要做

部分 Routine 支持 webhook 和外部事件；触发器可能是版本、团队和连接器相关能力。

### 操作步骤

1. 先核实你当前账户是否显示 webhook / 事件触发器，找不到就不要假设有。
2. 建立最小测试事件，只携带非敏感 ID，不公开 webhook 密钥。
3. 设置幂等键、时间窗口、防重复规则、空数据处理和报警人。
4. 先让触发器只生成草稿；测试重复事件和源系统不可用，再考虑长期启用。

### 验收标准

重复触发不会造成重复发布或重复付款，异常请求留下失败记录。

### 常见误区

Webhook URL 和 secret 不是可写进公开仓库的演示内容。

**官方参考：** https://docs.x.ai/grok-bot/skills-routines-and-automations

## 23. X 上的 @bot：条件与使用边界

**分类：** 核心能力　**预计学习：** 12 分钟　**难度：** 入门

理解社交平台入口和限制，不靠猜测故障。

### 为什么要做

官方提供通过 X 提及 @bot 的工作方式，但地域、内容类型与账号安全策略可能影响响应。

### 操作步骤

1. 先读官方 Tag @bot on X 文档，确认当前功能是否对账号和地区开放。
2. 用不含隐私的普通文本帖子做低风险测试，不公开内部邮箱、客户信息。
3. 若未响应，核对是否同时提及 @grok、是否包含视频、是否受到审核限制。
4. 把最终外发动作依旧交给本人审批；不要把它作为自动陌生人营销通道。

### 验收标准

能从官方列出的限制中解释可能未响应的原因，并保留测试链接。

### 常见误区

X 上 @bot 的名称可能被第三方冒用，不能授予不明账号权限。

**官方参考：** https://docs.x.ai/grok-bot/tag-on-x

## 24. 云端电脑故障：Recover、Update、Reset

**分类：** 安全与排障　**预计学习：** 15 分钟　**难度：** 入门

优先保全工作和登录，再处理设备问题。

### 为什么要做

Recover/Update 与 Reset 的破坏性并不相同；Reset 可能丢失最近未同步工作。

### 操作步骤

1. 先截取错误消息、失败时间、当前 Bot 名称，确认不是账号额度或审批卡片在等待。
2. 依次尝试 Retry、重开会话、重启 Grok Bot、检查客户端更新。
3. 仍不可达时按官方路径尝试 Recover computer 或 Update Bot’s Computer。
4. 只有在明白可能丢失近期工作并且前几步失败时，才考虑 Reset；完成后检查关键文件与登录状态。

### 验收标准

故障记录保留，能够说明恢复方法及哪些工作可能需要重跑。

### 常见误区

不要把 Reset 当成“刷新一下”，也不要将恢复操作与隐私清除混为一谈。

**官方参考：** https://docs.x.ai/grok-bot/troubleshooting

## 25. 共享电脑、凭据和隐私删除

**分类：** 安全与排障　**预计学习：** 20 分钟　**难度：** 入门

明确 Bot 消失、文件消失、授权撤销是不同步骤。

### 为什么要做

同账户的 Bots 共用云端电脑文件与会话；删除 Bot 后某些共享电脑内容可能继续存在。

### 操作步骤

1. 列出账号中有权限的 Bot、插件/连接器、登录会话、文件、Skills、Routines。
2. 按重要性备份必要成果，注销不再使用的网站会话并撤销第三方授权。
3. 删除不再需要的 Routine / Bot 前阅读不可恢复说明；不要误以为删除 Bot 会清理所有文件。
4. 检查共享电脑上的机密文件和凭据，必要时由组织管理员按数据政策执行留存/删除。

### 验收标准

完成清理清单，确认旧 Bot 无法使用，且所有残留授权均经核对。

### 常见误区

Team Bot、私人 Bot、共享模板的隐私边界不同；切勿把会话隔离误当文件隔离。

**官方参考：** https://docs.x.ai/grok-bot/approvals-security-and-privacy

## 26. 建立质量 SLO、审计台账和回滚预案

**分类：** 管理与增长　**预计学习：** 22 分钟　**难度：** 进阶

把 Grok Bot 当生产流程管理，而不是一次演示。

### 为什么要做

持续可靠性依赖可度量的准确率、失败率、延迟、人工复核与紧急停用策略。

### 操作步骤

1. 选一个非敏感的高频任务，记录手工基线：耗时、样本量、错误数。
2. 运行 10 次并记录成功、部分完成、失败、误动作与人工审核时间。
3. 制定门槛，例如关键事实核对率 100%，不允许未经审批外发；不达标只保留手动触发。
4. 为任务准备暂停 Routine、撤销授权、恢复旧成果、通知责任人的回滚清单。

### 验收标准

形成可审阅的 10 次运行台账，能解释净收益和失败兜底，而不是只统计任务次数。

### 常见误区

不能因为演示成功一次就放开所有审批；未测量数据不得宣传为节约成本。

**官方参考：** https://docs.x.ai/grok-bot/use-cases

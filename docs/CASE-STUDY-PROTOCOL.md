# 实战案例证据协议｜不造假、不泄露客户数据

## 四级可信度

- **L0 想法**：未经执行的场景和猜想，只能用于脑暴；绝不能标注“实测”。
- **L1 模板**：已写完整提示词，有输入与验收说明，但没有运行记录。本仓库默认大多数提示词属于 L1。
- **L2 复现**：在受控测试数据上运行，留有时间、产品版本、截图/文件和至少一次独立复核；可以写“测试环境验证”。
- **L3 真实生产案例**：真实授权业务任务，有证据、异常记录、用户许可的脱敏材料与质量复核；才能写“真实交付”。

## 真实案例必须填写的字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务目的 | 是 | 业务真实需求，不可夸大任务结果 |
| 日期、时区、产品版本、账号能力 | 是 | 便于复现；不展示账户隐私信息 |
| 输入与授权范围 | 是 | 数据来源合法、有明确处理目的 |
| 运行次数、成功/失败样本 | 是 | 不可只选好看的成功片段 |
| 输出证据 | 是 | 截图、原始链接、脱敏文件与版本号 |
| 人工审核与纠错工时 | 是 | 计算净收益需要扣除 |
| 操作前后的状态对比 | 是 | 只在确有对照时声明改进 |
| 风险与失败处理 | 是 | 记录停机、权限中断、审批等 |
| 可公开许可与脱敏审核 | 是 | 不能复制客户私聊或敏感文件原文 |

## 可公开的案例措辞

正确：「测试数据运行 10 次，成功 8 次，2 次连接失败，人工复核约 12 分钟/次。」

错误：「AI 员工 100% 全自动赚钱、月入十万」——没有可信证据时严禁这样宣传。

样例记录表参见 [TEST-RUN-LOG.csv](../templates/TEST-RUN-LOG.csv)；不要填写虚构的样例真实数字。

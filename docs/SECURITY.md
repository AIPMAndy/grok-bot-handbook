# Grok Bot 安全与审批保姆级清单

> 核心原则：准备可以自动化，外部不可逆动作需要先给人看。

## 必须理解的四件事

1. **多个 Bot 可能共用一个云电脑及登录会话。** 一个 Bot 的隐私资料不能仅靠不同的聊天列表隔离；涉及不同客户或权限层级，使用独立账户/授权策略。
2. **审批需要覆盖外部后果。** 发送信息、公开发布、购买/转账、删除、权限变更及生产系统更新，应默认暂停并取得具体授权。
3. **机器人并不自动等于正确。** 必须要求来源链接、交付物和失败记录；重要数字手动复核。
4. **帐号安全高于流畅体验。** 使用 Take over 完成真人密码、MFA/CAPTCHA，不要输入到普通对话或共享模板里。

## 建议的 Bot 描述安全段落

```text
你只能使用明确授权的数据源、文件夹和网站。默认先读取和草拟。
凡涉及向外发送、公开发布、购买/付款、删除、覆盖文件、修改权限、生产环境更改或接受法律条款，必须先返回完整的操作预览，说明对象、目标、内容、金额/范围、潜在后果，等待我对这一项具体动作的批准。
没有权限、来源不可访问、数据过期或证据缺失时停止相应动作并报告，不要绕过登录、MFA、CAPTCHA 或访问限制。不得把敏感数据写入公共共享模板。
每项交付包含来源/证据、完成与未完成清单。
```

## 按月复核

- 安装了哪些连接器？分别用来执行哪项任务？
- 是否存在不需要却仍登录的邮箱、CRM、银行或生产账号？
- 是否有超出职责范围的 Auto Review Allow automatically 规则？
- 哪些 Routine 仍在运行，是否应暂停？
- 分享 Bot 模板之前是否删除私人 URL、秘钥和客户信息？
- 删除 Bot 后，是否还需在共享电脑登出、撤销第三方应用授权、清理文件？

**官方出处：** [Approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy) 、[FAQ](https://docs.x.ai/grok-bot/faq)。
